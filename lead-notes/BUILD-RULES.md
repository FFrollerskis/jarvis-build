# BUILD-RULES (felles for alle byggere fra 2026-11-26; gjelder i tillegg til pakkens egen byggeordre)

Eierens krav (D-497, ordrett): «bygger alt reelt og ekte å ikke noe halvveis å test under veis det du bygger så vi slipper å fikse så mye når alt er ferdig». Du bygger derfor KOMPLETT og ekte: ingen stubber, ingen «TODO senere», ingen sovende kode uten tester. Det som ikke kan fullføres uten eierens credential/konto/maskinvare/jus bygges helt til grensen (ekte kode + kontrakts-/fake-server-tester) og meldes som `BLOCKED_EXTERNAL` med eksakt sjekkliste. Alt annet som ikke gjøres merkes `DEFERRED`/`PARTIAL` med begrunnelse (aldri stille utelatt). Alt er `DORMANT`/flagg AV og `NOT VERIFIED` til eieren har kjørt NAS-/live-trinn.

## 1. Arbeidsform
- Pakkens worktree og gren står i byggeordren. Arbeid KUN der. Før første push: `git remote get-url origin` = `https://github.com/FFrollerskis/jarvis-build.git`. Push `git push origin <gren>` etter HVER milepæl/fiks (en annen bygger må kunne fortsette fra det som ligger på GitHub + dine notater). Notater: `/tmp/pg-home/<pakke>-notes/NOTES.md` (opprett mappen) etter hver milepæl: hva er gjort, hva er neste, kjente feller.
- Les prosjektreglene i `/home/user/jarvisbuild/CLAUDE.md` (regel 1-12). Særlig: 3 adaptere (ingen leverandør-SDK i kjernen), 4 alt merket (person, tenant, memory space, kilde, task_id/session_id), 6 rask bane hopper aldri over Policy Gateway, 7 ubetrodd innhold er data, 11 D-41 (maksimal leverandørkapabilitet, A-D styrer HVORDAN), 12 D-64 (kjerne vs adapter: kjør og LOGG porten før en ekstern leverandør velges; meld `CORE_DEPENDENCY_DECISION_REQUIRED=true/false` først i rapporten).
- Rød-først der det går: skriv testen som feiler mot dagens kode, vis at den feiler, bygg, vis at den passerer. Mutanter: lag et mutantsett (minst 20-40 for sikkerhetskritisk kode; drept/overlevende rapporteres; overlevende er enten ekvivalente (forklar) eller testhull (fiks)). Differensialtest: flagg AV skal være byte-/atferdslikt main der pakken endrer eksisterende flater (baseline-fixturer: `wph1-flag-off-selection-baseline`, `wph2-flag-off-main-parity`, wpn1-differensialer).
- Nye flagg: alle AV som standard; navn `JARVIS_<DOMENE>_*`; legg i `infra/local/service-env.mjs`/compose-regenerering der kodebasen krever det (guards: d212/d240/d339, `remediation-2-compose-isolation`, env-drift).
- Nye migrasjoner: KUN det byggeordren tildeler (nummerområde står der); append-only; expand/contract; RLS med FORCE + 4 policies + WITH CHECK der tabellen er tenant-eid; `scope-fk-baseline` skal forbli tom; oppdater erasure-coverage (`d395`) for nye tenant-tabeller. Aldri rediger en eksisterende migrasjon.
- Ingen delte docs (DECISIONS_AND_ASSUMPTIONS, OPEN_QUESTIONS, FINDINGS_LEDGER, PROJECT_STATUS, CLOSURE_MATRIX, OWNER_ACTIONS, CLAUDE.md, CANONICAL_SPEC): lead/docs-agent fører dem; du FORESLÅR tekst i rapporten. Du SKAL skrive en runbook `docs/runbooks/<PAKKE>.md` (norsk): hva er bygget, flagg, eierhandlinger (NAS-trinn), `NOT VERIFIED`, rollback.
- `.gitleaksignore` er IKKE din: kjør gitleaks på dine commits; falske positiver rapporteres med fingeravtrykk (commit:fil:regel:linje), aldri skriv ekte-lignende hemmeligheter i fixturer (bygg verdier sammensatt ved kjøring).

## 2. Maskin- og testregler (hardt vunnet)
- `export HOME=/tmp/pg-home npm_config_manage_package_manager_versions=false PATH=/opt/node22/bin:$PATH NODE_OPTIONS=--max-old-space-size=2048` (men ikke i samme kommando som `git commit`: bruk `HOME=/root` for commit så git-identitet finnes).
- DB-tester kan IKKE kjøre som root: `su postgres -s /bin/bash -c 'export HOME=/tmp/pg-home npm_config_manage_package_manager_versions=false PATH=/opt/node22/bin:$PATH NODE_OPTIONS=--max-old-space-size=2048; cd <worktree> && timeout -k 5 900 pnpm exec vitest run --maxWorkers=2 <filer>'`. Maks 2 vitest-arbeidere, alltid `timeout -k 5`. Maskinen har 4 CPU / 15 GB og deles med flere byggere: aldri mer enn 2 arbeidere fra deg, ingen parallelle tunge jobber fra deg.
- FULL suite: kun som ENESTE tunge jobb under `flock /tmp/fullsuite.lock` (kø; ca. 40-60 min), i bakgrunnen med logg, poll med `timeout N bash -c 'until grep -q DONE <logg>; do sleep 10; done'` (foreground-`sleep` er blokkert utenom korte). Uten `embedded-postgres-ipv4-contention*` (henger i sandkassen; ikke kjør den). Kjør ellers berørte filer + modulens hele test-mappe + `apps/api/test` (HELE mappen hvis du rører `apps/api/src/server.ts`/`main.ts`/`worker-main.ts`) + migrasjons-/skjema-/compose-/doc-vaktene.
- KJENTE sandkassefeil som IKKE er dine (5): `wpc3-review1-hardening` F10a/b/c, `break-glass-guard`, `nas-ua0-gate` «friskt system»; `embedded-postgres-port-lease` er belastningsfølsom (kjør alene). Alt annet rødt er ditt.
- Kildevakter i `apps/api/test` (`wpn1-job-delivery`, `d449-delegated-tool-jobs-cloud`, `wpn1-guard-env`, `wpn1b-structure`) bruker NAIVE kommentarfjernere og eksakte tellinger: skriv aldri `/*` eller `*/` i strenger/kommentarer i `apps/api/src/server.ts`/`main.ts`; nye brukere av `servedByCloudModel` osv. må inn i vaktenes tellinger bevisst.
- Write-verktøyet dekoder `\uXXXX`-escapes i innhold til rå tegn: bruk `String.fromCodePoint`/python eller kontroller med skript når regex-literaler med slike tegn skrives.
- Statiske kontroller før ferdig: `pnpm -r --workspace-concurrency=2 run typecheck`, `pnpm lint`, `pnpm check:containment` (alle exit 0), og `set -o pipefail; /tmp/gitleaks-bin/gitleaks detect --source . --no-banner --log-opts="<base>..HEAD" 2>&1 | tail -3`.
- Ingen `rm -rf`, ingen `git reset --hard`/force/rebase/stash, ingen sletting av grener, aldri push til `main`; drep kun egne prosesser (aldri `pkill`); spawn ikke egne agenter; du kan ikke skrive utenfor worktreen og `/tmp/pg-home/<pakke>-notes/` + `/tmp/lead/gap/` kun lesing.
- Små commits (`feat:`/`fix:`/`test:`/`docs:`) med trailerne `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>` og `Claude-Session: https://claude.ai/code/session_01DjaWBW7BCa7u4mUsiHFwH4`. Norsk i dokumentasjon/brukertekst, engelsk i kode/identifikatorer. Statusord: WIRED / DORMANT / BUILT_UNWIRED / PARTIAL / DEFERRED / BLOCKED_EXTERNAL / NOT_BUILT; aldri «VERIFIED» uten et kjørt artefakt.

## 3. Uavhengig review kommer etter deg
Én kombinert A+B-reviewer (to for høyrisiko: identitet/authority/secrets/egress/audit/penger) leser ditt arbeid kald. Gjør det lett: oppgi i rapporten «security surfaces» (fil:linje), nøyaktige testkommandoer, hva som er mutantsjekket, og hva du er usikker på.
