## Lead-beslutninger (D-497; bygg etter disse, avvik kun med begrunnelse + kodebevis)
1. **Lukket enhetstype** (`devices.kind`) og server-side tabell kind -> tillatte kanaler (konstant i kontrakt-/domenelag, én kilde): `iphone` -> {mobile}; `mac` -> {desktop}; `windows` -> {desktop}; `web_browser` -> {web}; `watch` -> {watch}; `voice_gateway` -> {voice}; `telegram_gateway` -> {telegram}; `api_client` -> {api}; `service` -> {system}; `legacy_unknown` -> se pkt 3. Les `ChannelSchema` og `OWNER_STEP_UP_CHANNELS` (`class-d-pipeline.ts`) og hvordan `api`/`system` brukes i eierflyter/skript/jobber før du setter mappingen; ingen enhetstype skal kombinere en step-up-kanal med en lavtillits-rolle. Skriv mappingen og begrunnelsen i runbooken.
2. **Nekt, ikke nedgrader**: kanal som ikke hører til enhetstypen => `channel_not_allowed_for_device_kind` + revisjonsrad, fail-closed. Typen settes KUN av serveren ved innrulling (innrullingsbilletten bærer typen; klienten kan ikke velge/endre den). Endring av `kind` for eksisterende enhet krever eksisterende step-up eller break-glass.
3. **Eksisterende enheter** (`legacy_unknown` etter migrasjon): kjente `kind`-verdier mappes til lista; ukjent => `legacy_unknown`, som beholder dagens oppførsel for IKKE-step-up-kanaler men aldri kan gi step-up-oppfyllende `signed` på web/desktop/mobile/api før enheten er innrullert på nytt. Eierens egne kontroller (kill switch/connector-frys m.m.) MÅ ikke låse eieren ute ved oppdatering: derfor modus (pkt 4) og en tydelig re-innrullingsvei.
4. **Modus**: `JARVIS_STEPUP_CHANNEL_BINDING=observe|enforce`, standard `observe` (logger/revisjonsfører «ville nektet» uten å nekte = identisk med main + revisjonsstøy), `enforce` settes av eieren etter å ha gjennomgått enhetslisten (runbook). **Fail-closed kobling**: de høyrisiko-flaggene som venter på S1 (`JARVIS_PERSONAL_*`, `JARVIS_GROWTH_WRITE_*`, `JARVIS_COMMS_OUTBOUND`, `JARVIS_SITUATION_SIGNALS` - verifiser faktisk liste i koden) skal ikke gi effekt (kapabiliteten nektes med klar årsak `stepup_binding_not_enforced` og vises i helse/status) når `JARVIS_STEPUP_CHANNEL_BINDING` ikke er `enforce`. Ingen krasj ved oppstart; ingen stille suksess.
5. **Ingen ny leverandør/bibliotek** (regel 3/D-64: ikke utløst); Ed25519-enhetsnøkler er Jarvis-eide og uendret.
